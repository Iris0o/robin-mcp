> [!WARNING]
> Это **экспериментальная неофициальная** интеграция с внутренним файловым API Studio. Проект не связан с производителем ROBIN и не является его API. Проверено на Studio **2.24.4.101653** (схема исходника **5.5.0**), совместимость с другими версиями не заявлена.

## ✨ Возможности

- Чтение и запись `.robin-project` напрямую, без запуска окна Studio, шпионов и захвата экрана.
- Вставка готовых действий из нативных шаблонов проекта, включая вложенные последовательности.
- Создание и обновление параметров, переменных и Web/Win-ресурсов.
- Защита от конфликтов: проверка SHA256-ревизии и автоматическая резервная копия при каждой записи.
- Проверка структуры проекта: идентификаторы, ссылки, родительские последовательности.
- Только стандартная библиотека Python, без сторонних пакетов.

## 📋 Требования

- Windows с PowerShell 5.1 и .NET Framework 4.8
- Python 3.10+
- Установленная ROBIN Studio (по умолчанию `C:\Program Files\Robin Platform\2.0.0\Studio`)

## 🚀 Быстрый старт

1. Клонируйте репозиторий:

   ```powershell
   git clone https://github.com/Iris0o/robin-mcp.git
   cd robin-mcp
   ```

2. Добавьте сервер в конфигурацию MCP-клиента по образцу из [`mcp-config.json`](mcp-config.json). Замените `<ПУТЬ_К_РЕПОЗИТОРИЮ>` на путь к клону, а при необходимости задайте полный путь к Python.

3. Для проверки запустите сервер вручную. Он ждёт JSON-RPC на stdin, так что пустой экран — это нормально:

   ```powershell
   python robin_mcp.py
   ```

### Переменные окружения

| Переменная | Назначение |
|---|---|
| `ROBIN_STUDIO` | Папка с `Studio.exe` |
| `ROBIN_WORKSPACE` | Разрешённая папка записи. По умолчанию `projects` рядом с сервером |

## 🔄 Порядок работы

1. `list_projects` находит проекты в `Documents\Robin\Studio\Projects`.
2. `import_project` копирует проект вместе с ресурсами в рабочую папку, либо `create_project` создаёт пустой исходник и `.robin-prjmeta`.
3. `read_project` возвращает XML, идентификаторы элементов и `revision`.
4. Передавайте эту ревизию как `expected_revision` при изменениях. Каждая успешная запись возвращает новую ревизию и путь резервной копии.
5. Откройте полученный `.robin-project` в Studio, сохраните и соберите проект перед выполнением.

> [!IMPORTANT]
> **Закрывайте редактируемый проект в Studio на время работы MCP.** Синхронизации с открытым редактором нет: он может перезаписать файл своей копией. Проверка SHA256 обнаруживает изменения до записи, но не блокирует файл между процессами.

## 🧰 Инструменты

| Инструмент | Назначение |
|---|---|
| `list_projects`, `import_project` | Поиск и копирование проектов |
| `create_project`, `read_project` | Создание и чтение исходника |
| `list_action_templates` | Родные XML-шаблоны действий из существующего проекта |
| `add_action` | Вставка действия, включая вложенные последовательности; новые ID и переназначение внутренних ссылок |
| `set_parameter` | Значение параметра или ссылка на ресурс/результат |
| `add_resource`, `update_resource` | Переменные, Web/Win-элементы и другие ресурсы |
| `set_properties` | Имя, включение, задержка, точки останова, флаги ресурсов и другие атрибуты |
| `remove_element` | Удаление действия или ресурса с проверкой ссылок |
| `validate_project` | Проверка ID, ссылок и родительских последовательностей |

### Примеры значений

```jsonc
// строка
{"type": "Robin.String", "value": "Привет"}

// ссылка на ресурс или результат
{"resource_id": "UUID"}
```

Простые типы: `Robin.String`, `Robin.Numeric`, `Robin.Boolean`, `Robin.FilePath`, `Robin.FolderPath`.

Для сложных типов (`Robin.WebElement`, `Robin.WinElement`, коллекции) передайте `serialized_value` в родном формате поля `Value`, взяв пример из `read_project`, и `display`. XPath, например, находится внутри сериализованного `RobinWebElement`.

`add_action` принимает полный `action_xml` из `list_action_templates`. Параметры, результаты, контракт и версия реализации сохраняются. Внешние ссылки шаблона должны существовать в целевом проекте. Автоматического каталога всех действий Studio пока нет.

## ⚙️ Как это устроено

`bridge.ps1` загружает `Studio.exe` как .NET-сборку, инициализирует загрузчик встроенных библиотек и вызывает `SafeProjectEncryptedFileProvider.Open/Save`. Окна Studio и её точка входа не запускаются. Чтение выполняется на временной копии, потому что родной `Open` запрашивает доступ на запись. Ключи шифрования не извлекаются и не хранятся.

При сохранении XML проверяется родным `XmlSerializer` для `Robin.Schemes.ScenarioEntity`, затем выполняется обратное чтение. Файл заменяется после создания резервной копии в `backups/project-edits/<идентификатор пути>` рядом с сервером, вне каталога проекта. Хранить копии внутри проекта нельзя: Studio включает их в пакет, а распаковщик Robin не создаёт вложенные папки и сообщает «Не найден файл робота».

## 🚧 Ограничения

**Не реализованы:** компиляция, запуск и отладка, публикация, обновление открытой схемы в реальном времени.

Производные файлы (`.robin-scenario` со схемой исполнения 6.0.1, `.robin-impinfo`, `.robin-def`) MCP не пересобирает. В импортированных копиях они остаются от предыдущей сборки, поэтому запускать проект после правок нужно только после пересборки в Studio. Новые проекты содержат исходник и метаданные, без исполняемого пакета.

Проверены прямое чтение и обратное сохранение шести локальных проектов, а также работа MCP по stdio. Открытие нового проекта и выполнение изменённого процесса в самой Studio не проверялись. Валидация структуры не гарантирует корректность бизнес-логики, типов параметров, доступность пакетов или селекторов.
